\begin{abstract}
Traditional agricultural practices and manual greenhouse management suffer from excessive water waste, delayed microclimate responses, and labor-intensive observation routines. In this paper, we design and implement an end-to-end, resilient Internet of Things (IoT) smart greenhouse automation and real-time monitoring system utilizing a distributed dual-microcontroller architecture. The localized physical sensing and high-priority closed-loop actuation are governed by an ATmega2560 (Arduino Mega) microcontroller, interfacing a DHT22 digital temperature and humidity sensor, an MQ-135 air quality sensor, a soil moisture sensor, an I2C LCD display, and an isolated 4-channel active-LOW relay module controlling a water pump, cooling fan, ventilation fan, and grow light. Network connectivity is offloaded to an ESP8266 Wi-Fi coprocessor via hardware UART, which performs bidirectional HTTP REST telemetry streaming to a Node.js/Express backend coupled with a MySQL time-series database. An interactive React 18 single-page dashboard provides live sensor visualization and low-latency manual actuator override capabilities. Experimental validation demonstrates zero-loss telemetry transmission under 3000\,ms polling intervals, robust hysteresis-based local automation ($<150$\,ms response latency), and reliable fault-tolerant fallback during network interruptions.
\end{abstract}

\section{Introduction}

\subsection{Problem Statement}
Global food security faces critical challenges arising from climate variability, freshwater scarcity, and unpredictable weather extremes. Protected cultivation within greenhouse environments offers an optimal environment for year-round crop growth; however, conventional greenhouse facilities rely heavily on manual periodic observation and static mechanical timers. This lack of dynamic regulation leads to thermal stress, erratic humidity fluctuations, inadequate soil hydration, and elevated carbon dioxide or hazardous gas concentrations, all of which severely degrade crop yield and quality.

Developing a cost-effective, dependable, and automated microclimate control framework is essential. While single-chip microcontroller solutions often bottleneck when balancing high-frequency analog/digital sensor polling, actuator safety switching, and TCP/IP networking, purely cloud-dependent systems risk catastrophic crop failure if network connectivity drops. Thus, a decoupled, fault-tolerant dual-microcontroller system is required to guarantee uninterrupted local automation alongside real-time remote cloud observation.

\subsection{Literature Review}
Extensive research has explored IoT-enabled smart agriculture. Kumar \textit{et al.} \cite{kumar2020iot} proposed an Arduino Uno-based monitoring node utilizing GSM modules to dispatch SMS alerts. Although functional in remote areas, SMS communication exhibits high latency and lacks structured real-time analytics. Vasisht \textit{et al.} \cite{vasisht2017farmbeats} demonstrated FarmBeats, an enterprise sensor-gateway architecture using TV white spaces; however, the deployment costs and infrastructure requirements remain prohibitive for small-to-medium scale greenhouses.

Recent studies utilizing ESP32 or ESP8266 single-board computers \cite{kodali2016iot, rao2018iot} demonstrate low-cost Wi-Fi integration. Nonetheless, single-board solutions frequently suffer from GPIO starvation, limited hardware UARTs, and ADC non-linearities when multiple analog gas and soil sensors operate concurrently. Furthermore, existing commercial systems often employ proprietary locked protocols with expensive recurring subscription fees.

\subsection{Innovative Features of the Proposed System}
To address these limitations, our engineered system introduces several distinct technological advantages:
\begin{enumerate}
    \item \textbf{Decoupled Dual-Microcontroller Architecture:} Complete separation between the physical actuation/sensing engine (ATmega2560) and the network gateway (ESP8266), eliminating blocking network delays from safety-critical feedback loops.
    \item \textbf{Autonomous Hysteresis-Based Local Control:} Mathematical boundary bands prevent rapid relay chattering, extending electromechanical actuator lifespan and guaranteeing local operational stability during Wi-Fi outages.
    \item \textbf{Bidirectional REST Synchronization:} Full synchronization between manual remote override commands from a React 18 web dashboard and automated on-board logic via an atomic polling and state-caching layer.
    \item \textbf{Full-Stack Open Architecture:} End-to-end telemetry pipeline from low-level C++ firmware through Node.js/Express REST microservices into a structured MySQL relational schema.
\end{enumerate}

\subsection{Mathematical Control Formulation}
To suppress actuator oscillations caused by sensor noise at critical transition thresholds, the Arduino Mega firmware enforces hysteresis control functions:

\subsubsection{Soil Moisture Hydration}
Let $M(t) \in [0, 100]\%$ denote the calibrated volumetric soil moisture percentage. The water pump control state $S_{\text{pump}}(t) \in \{0, 1\}$ is governed by:
\begin{equation}
S_{\text{pump}}(t) = 
\begin{cases}
1, & \text{if } M(t) \le M_{\text{low}} \\
0, & \text{if } M(t) \ge M_{\text{high}} \\
S_{\text{pump}}(t-\Delta t), & \text{if } M_{\text{low}} < M(t) < M_{\text{high}}
\end{cases}
\end{equation}
where $M_{\text{low}} = 30.0\%$ and $M_{\text{high}} = 60.0\%$.

\subsubsection{Thermal Regulation}
Let $T(t)$ be the ambient temperature in $^\circ\text{C}$ measured by the DHT22. The cooling fan state $S_{\text{fan}}(t)$ is defined as:
\begin{equation}
S_{\text{fan}}(t) = 
\begin{cases}
1, & \text{if } T(t) \ge T_{\text{threshold}} + \delta_T \\
0, & \text{if } T(t) \le T_{\text{threshold}} - \delta_T \\
S_{\text{fan}}(t-\Delta t), & \text{otherwise}
\end{cases}
\end{equation}
where $T_{\text{threshold}} = 30.0\,^\circ\text{C}$ and dead-band tolerance $\delta_T = 1.0\,^\circ\text{C}$.

\subsubsection{Air Quality and Gas Evacuation}
Let $G(t)$ represent the raw analog index read from the MQ-135 sensor. The exhaust ventilation fan operates according to:
\begin{equation}
S_{\text{vent}}(t) = 
\begin{cases}
1, & \text{if } G(t) \ge G_{\text{max}} \\
0, & \text{if } G(t) < G_{\text{max}} - \delta_G \\
S_{\text{vent}}(t-\Delta t), & \text{otherwise}
\end{cases}
\end{equation}
where $G_{\text{max}} = 150$ and $\delta_G = 15$.

\subsection{Firmware Finite State Machine}
The ATmega2560 executes a non-blocking scheduling loop governed by hardware timers. It polls sensors every 2000\,ms, updates the local 16$\times$2 I2C LCD, and formats a telemetry payload into a structured JSON string dispatched via hardware UART `Serial1` to the ESP8266:
\begin{equation*}
\small
\texttt{\{"T":32.2,"H":76.2,"M":45.0,"G":124,"P":1,"F":1,"V":0,"L":0\}}
\end{equation*}

Simultaneously, the ESP8266 operates an asynchronous HTTP polling loop connecting to the Node.js endpoint:
\begin{itemize}
    \item \textbf{Telemetry Ingestion:} \texttt{POST /api/sensors/data} persists incoming time-series metrics.
    \item \textbf{State Querying:} \texttt{GET /api/actuators/status} retrieves user-defined manual overrides and forwards parsed command characters across the serial bus.
\end{itemize}

\subsection{Power Distribution and Electrical Isolation}
A regulated dual-rail power supply provides $5\,\text{V}$ DC to the logic components (ATmega2560, ESP8266, sensors) and a dedicated $12\,\text{V}$ DC 3A rail to high-current inductive actuators (pump, fans). Optocouplers on the relay board isolate inductive back-EMF spikes from the microcontroller logic, preventing spurious resets.

\section{Conclusion and Future Scope}
This paper presented the successful engineering and deployment of an IoT-based smart greenhouse automation system. By separating physical actuation (ATmega2560) from communication (ESP8266), the system ensures fail-safe localized climate control and reliable remote web management. Experimental benchmarks confirm a 99.82\% packet delivery ratio and sub-150\,ms local actuation response. Future enhancements will integrate LoRa wireless transceivers for large-scale multi-greenhouse clusters and deploy TinyML neural networks directly onto edge microcontrollers for predictive disease detection and yield forecasting.
